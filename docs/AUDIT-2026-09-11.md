Generated: 2026-09-11
Method: combined `app-audit-plan` + `audit-to-plan` + `code-review` + `security-review`, executed as 8 parallel

## CRITICAL

### ISSUE-001 — Cross-tenant data leak via `integrations.jobs.runNow`
**Verified.** `packages/api/src/router/integrations.ts:304`

Gated only by the caller's own-org `integrations.manage` permission, but calls `processDueJobs` →
`claim_jobs()` (`supabase/migrations/0033_background_job_leases.sql:14`), a `SECURITY DEFINER` function
revoked from `authenticated`/`anon` and meant only for the service-role worker. It claims and runs due jobs
**queue-wide across every organization** (no `organization_id` filter — `p_org_cap` only throttles per-org
concurrency within a claimed batch) and returns the full result, including other tenants' job outputs
(customs decisions, document extraction, notifications), straight to the caller. Any org admin with
`integrations.manage` can read other tenants' background-job results.

## HIGH

### ISSUE-002 — Drizzle schema is stale against migration 0031's tenant-safe composite FKs, across nearly every core table
**Verified.** `packages/db/src/schema/movements.ts:79` (+ integrations.ts, inbond.ts, documents.ts, alerts.ts, registry.ts)

Migration 0031 dropped ~30 single-column FKs (e.g. `movements_truck_id_fkey`) and replaced them with
composite `(col, organization_id) references parent(id, organization_id)` FKs plus ~50 new indexes/unique
constraints. None of this exists in the Drizzle schema — `movements.ts:79` still declares
`truckId: uuid(...).references(() => trucks.id, ...)`, the exact relationship the DB no longer has. Should
have been caught by `pnpm --filter @corridor/db verify:mirror`.

### ISSUE-003 — Customs gateway fixture polling can never advance past its first stage
**Verified.** `packages/integrations/src/customs/gateway/client.ts:94` (`filings` map), vs
`packages/api/src/services/customs.ts:120-157` (`customsClientFor` builds a fresh client — and fresh
`filings` map — on every call)

Every poll resets to `polls: 0` → 1 → always renders `stages[0]`. A movement filed under gateway mode
without real CBP/CBSA credentials never reaches accepted/released/held/rejected. Contradicts the file's own
doc comment ("a poll sequence unfolds like a real crossing").

### ISSUE-004 — In-bond mock/fixture state shared across all tenants in memory
**Verified.** `packages/integrations/src/customs/mock.ts:64` (`mockBonds`),
`packages/integrations/src/customs/gateway/client.ts:90` (`fixtureBonds`)

Both are module-level (process-wide) maps keyed only by `bondNumber`, read/written for every org using mock
or credential-less gateway mode. Two tenants picking the same demo bond number (plausible with synthetic
data) read/overwrite each other's in-bond status — a cross-tenant leak of application state, in memory
rather than a table, that runs against the repo's tenant-isolation principle. Also never evicted (unbounded
growth).

### ISSUE-005 — `customs.poll_status` makes an external HTTP call while holding an open DB transaction
**Verified.** `packages/api/src/services/jobs.ts:107` (still in `jobHandlers`, not `detachedJobHandlers`) →
`packages/api/src/services/customs.ts:652` (`await client.fetchStatus(ref)`)

The sibling `customs.decide` handler was already fixed for this (moved out of the transaction);
`customs.poll_status` — which re-enqueues itself every `POLL_INTERVAL_MS` until terminal or 48h — was
missed. A slow/hanging gateway pins a pooled DB connection for the call's duration on every poll.

### ISSUE-006 — `DataTable` row click has no keyboard equivalent (WCAG 2.1.1 failure)
**Verified.** `packages/ui/src/components/data-table.tsx:216-229`, `packages/ui/src/components/table.tsx:28-32`

`onRowClick` is wired only to `onClick` on a bare `<tr>` — no `role`, `tabIndex`, or `onKeyDown`. A
keyboard-only user cannot reach or activate a row action at all. 3 consumers outside `packages/ui` use
`onRowClick`.

## MEDIUM

### API / Security

- **ISSUE-007** — CSV export vulnerable to Excel/Sheets formula injection: `csvField()` doesn't neutralize
  leading `=`/`+`/`-`/`@` — `packages/api/src/services/reporting-export.ts:18-22`, reachable via
  `party.ts:227-270`, `reporting.ts:147-195`.
- **ISSUE-008** — `reporting.crossings/export/run` require `report.read` AND `movement.read` (should likely
  be OR, like `pdf.ts`'s equivalent) — `packages/api/src/router/reporting.ts:137,147,202`. A
  "reporting-only" custom role with just `report.read` is silently locked out.
- **ISSUE-009** — Rate limiting fails open uniformly on Redis outage, including billing/invite/device-
  registration endpoints, with only a `console.error` — `packages/api/src/infra/ratelimit.ts:198-201,239-242`.

### DB / Schema

- **ISSUE-010** — `jsonb` used for fixed-shape, always-read-by-name address fields across 4 tables
  (`partners.address`, `shipments.delivery_address`, `organizations.billing_address`, `drivers.us_address`),
  violating the "jsonb is for free-form metadata only" rule.
- **ISSUE-011** — SECURITY DEFINER `search_path` hardening was regressed by migration 0036
  (`set search_path = public`, unqualified refs) then re-fixed by 0038 — net-safe on a fully migrated DB,
  but shows the qualification discipline wasn't durable; worth a lint/CI guard.
- **ISSUE-012** — 6 FK columns referencing `ports` (`entry_port_id`, `destination_port_id`, etc. on
  `shipments` and `in_bond_records`) have no index anywhere — seq-scan risk on port-filtered queries.

### Domain / Integrations

- **ISSUE-013** — Same "ACE ships CA→US / ACI ships US→CA" business rule implemented independently in
  `registry.ts:343` and `movement-validation.ts:188` — drift risk on a future regime change.
- **ISSUE-014** — No Stripe `idempotencyKey` on checkout/portal session creation —
  `packages/integrations/src/stripe.ts:164,186` — a retried call can mint duplicate sessions.
- **ISSUE-015** — `valueAmount` (declared cargo value) modeled as floating point, not integer cents/decimal
  — `packages/domain/src/shipment.ts:146`, `document.ts:45,105`.
- **ISSUE-016** — Same latent "fresh client = lost state" defect as ISSUE-003 exists in the mock client's
  `fetchStatus`, currently unreached but a trap for future callers —
  `packages/integrations/src/customs/mock.ts:81-84,201-212`.

### AI / PDF

- **ISSUE-017** — No size/token cap on document text sent to the extraction model (unlike the classifier's
  8192-byte cap) — `packages/ai/src/document-intelligence/model-extractor.ts:58`.
- **ISSUE-018** — No timeout/abort signal on `generateObject`/`embed`/`embedMany` calls —
  `model-extractor.ts:69`, `copilot/embedder.ts:39,43`.
- **ISSUE-019** — Retrieved org-authored knowledge is concatenated into the copilot system prompt with only
  a `[K1]` label, no escaping/fencing — weak prompt-injection resistance for content one org member writes
  and another's copilot session reads — `packages/ai/src/copilot/prompts.ts:10-25`.
- **ISSUE-020** — `packages/pdf` templates have no internal page/row cap of their own (the only guard lives
  in `packages/domain/src/pdf.ts:32` for one report type; `table-report.tsx` rows are unbounded within the
  package itself).

### Auth / UI / Config

- **ISSUE-021** — `resolveUser`/`toSessionUser` (the single source of truth for turning a Supabase client
  into a `Session`) has no dedicated test file — `packages/auth/src/session.ts:34-70`.
- **ISSUE-022** — Theme localStorage key `"corridor-theme"` hardcoded independently in two places with no
  shared constant — `packages/ui/src/components/theme-toggle.tsx:7` vs `apps/web/src/app/layout.tsx:36`. A
  future rename breaks SSR flash-prevention silently.
- **ISSUE-023** — `Checkbox`, `RadioGroup`/`RadioGroupItem`, `Switch`, and raw `Table` primitives are
  exported but have zero call sites outside `packages/ui` — maintained-but-unused surface area.
- **ISSUE-024** — `@corridor/config` exports `./eslint/next.js` in `package.json` but the file doesn't
  exist on disk — broken package export, currently unused so unnoticed.

### Web app

- **ISSUE-025** — `PUBLIC_PATHS` lists `/auth/confirm`, but no such route exists anywhere in the app — dead
  allowlist entry — `apps/web/src/proxy.ts:9`.

### Mobile

- **ISSUE-026** — Expo push token (classified by the app's own README as a "bearer capability") sits in
  plaintext `AsyncStorage` while queued in the offline outbox, inconsistent with its stated sensitivity —
  `apps/mobile/src/lib/outbox-client.ts:44-49`, `outbox.ts:314-318`, `push.ts:57-60`.

### Recent changes

- **ISSUE-027** — Trigram indexes added in migration 0034 don't match the actual search predicates:
  `movement.list`'s driver search matches a *concatenated* `first_name || ' ' || last_name` expression that
  no single-column index can accelerate; `trip_number`/`customs_reference_number` also searched but
  unindexed — `supabase/migrations/0034_search_indexes.sql` vs `packages/api/src/router/movement.ts:150-158`.
- **ISSUE-028** — Customs decision is applied against a stale in-memory movement snapshot across two
  separate transactions with no optimistic-concurrency guard (`UPDATE ... WHERE id = m.id`, no
  `AND status = from`) — a concurrent edit during the external gateway call can be silently clobbered —
  `packages/api/src/services/jobs.ts:197-237`, `packages/api/src/services/movements.ts:260-264`.

- **ISSUE-041** — `packages/config`'s base ESLint config only extends untyped `tseslint.recommended`, not
  `recommendedTypeChecked`/`strict` — type-aware rules like `no-floating-promises` aren't enforced
  monorepo-wide via lint (not a claim violation, just a gap).
